Super.img Unpacker

Extracts Android dynamic-partition super.img images (sparse or raw, LP/liblp metadata) entirely client-side — nothing is uploaded anywhere. Partitions stream straight to a folder on your device via the File System Access API, so multi-gigabyte images don't need to fit in memory.

4. Security scan — find Device Administrator & security-plugin APKs

Scans the selected partitions' file systems directly (ext4 or EROFS, auto-detected) for .apk files, checks each app's manifest for Device Administrator capability, and flags names that look like security/MDM plugins (a separate, looser heuristic). The scan itself never modifies anything; removal (section 5 below) is a distinct, explicit step.

5. Remove flagged apps & build a patched super.img

Read before using this. This tool can delete the selected apps' files from the loaded partition images and produce a new, patched super.img you can flash with fastboot flash super <file>. It cannot and does not:
  • disable Android Verified Boot (AVB) / dm-verity, or re-sign vbmeta — a partition whose content changed will usually fail its verity hash unless you separately disable verification (e.g. fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img) on an unlocked bootloader;
  • guarantee your device will boot afterward — a mismatched/locked bootloader, A/B slot, or OEM-specific partition layout can still make this unsafe; flash at your own risk and keep a backup of the original super.img;
  • free the removed apps' underlying storage — their data blocks/inodes are simply abandoned in place (never reused by anything), not reclaimed, so the patched image is the same size as the original.

Checkboxes below are pre-selected for apps flagged as Device Administrator-capable or security-plugin-like; review and adjust before removing. Removal happens in memory against the loaded image; nothing is written back until you build and download the patched file.

6. Remove Device Lock Components fixed targets

What this does. This action removes exactly three hardcoded files, by their exact path — regardless of what the scan above reports (the scanner can't read some compressed EROFS APKs' contents, so it must never be relied on to decide whether these files exist):
  • product_a/priv-app/SecurityCom/SecurityCom.apk — com.scorpio.securitycom
  • system_ext_a/app/TranPluginApp/TranPluginApp.apk — com.transsion.spl
  • system_ext_a/app/TranDaemonApp/TranDaemonApp.apk — com.transsion.spld
It verifies all three exist before changing anything (if even one is missing, it stops and reports exactly which, with no changes made), removes only those exact files (never a containing folder, never any other partition/APK/APEX/property), and produces super_MODIFIED.img — the original file is never overwritten. Same AVB/dm-verity/vbmeta caveat as above applies, and this never flashes anything.
